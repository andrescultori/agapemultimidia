# Admin panel (`/admin/`)

Lets the client edit prices, the buy link, KPIs, videos, hero image and general links of a page without touching code. Currently controls `/pro/`; `/black/` and the home are added the same way (see "Adding a page").

## How it works
- The pages keep their original text in the HTML. When they open, `shared/site-settings.js` asks `GET /api/settings?page=pro` and replaces the marked values (`data-b`, `data-buy`, `data-kpi`, `data-link`, `data-video`, `data-hero-img`). If the request fails, the original text stays.
- Login: allow-listed email → 6-digit code (Resend) → 8-hour session cookie (HttpOnly, Secure, SameSite=Strict).
- Editing: **save draft → preview (`/pro/?preview=draft`) → publish**. Publishing shows a diff and highlights price changes. Every publish is a row in `settings_versions` (who, when, changed fields); "Restaurar" copies an old version back into the draft.
- Public reads are cached 60 s at the edge, so a publish is live within about a minute.
- Not editable here (static in the HTML): `<title>`, meta description and share-preview (og) tags. Search and WhatsApp previews keep the original text. The page `<title>` is updated in the browser only for the discount %.

## Stack
- **Database and images: Supabase** (tables in their own schema `agape_admin`, images in a public bucket `site-images`). Used for testing now; for production decide between a dedicated Supabase project (paid tier does not pause) and Cloudflare D1/R2.
- **API:** the same handlers run as Vercel Functions (`api/`) or Cloudflare Pages Functions (`functions/`, via `functions/_adapter.js`). Only the Vercel path has been exercised end to end; the Cloudflare path is untested.
- **Email:** Resend.

## Setup checklist (once)
1. **Supabase:** run `db/schema.sql` in the SQL editor, then `db/app-role.sql` (creates the restricted login `agape_admin_app`, which can touch only the three `agape_admin` tables; both are already applied to the test project). Set that role's password yourself in the SQL editor: `alter role agape_admin_app with password '<long random password>';` (use letters and digits only, so the URL needs no escaping). Create a **public** bucket (Storage → New bucket; the test project uses `fabio-site-images`) and set `SUPABASE_BUCKET` to its name.
   - `DATABASE_URL`: click **Connect** in the Supabase top bar → *Transaction pooler*, copy the string, then change the user from `postgres.<ref>` to `agape_admin_app.<ref>` and put the new password in. Do not use the master `postgres` password.
   - `SUPABASE_URL`: Project Settings → API → Project URL. `SUPABASE_SERVICE_KEY`: Project Settings → API Keys → the `sb_secret_...` key (server-only; it bypasses all security rules).
2. **Resend:** for tests set `RESEND_FROM=onboarding@resend.dev` and put only your own Resend-account email in `ADMIN_EMAILS` (that sender delivers only to the account owner). For Fábio: verify `agapemultimidia.com.br` (add the SPF/DKIM records Resend shows at the DNS host), then use a `no-reply@agapemultimidia.com.br` sender. Create an API key with *sending access* only.
3. **Environment variables:** see `.env.example`. Vercel: Project → Settings → Environment Variables (Production and Preview). Cloudflare: project → Settings → Variables and Secrets (type Secret). `SESSION_SECRET` is generated by you (`openssl rand -base64 32`). Redeploy afterwards.
4. Deploy, open `/admin/`, log in, press "Publicar…" once with no changes to confirm the round trip.

### Hosting notes
- **Vercel:** Hobby is non-commercial; a client site belongs on Pro. `.vercelignore` keeps docs, SQL, tests and tooling out of the deployed static files.
- **Cloudflare (planned):** use the client's own account with André as a member (domain, billing and data stay with the client; R2 would need their payment method). `npm run build:cf` copies only the public folders to `dist/` and writes `_redirects`/`_headers`; `wrangler.toml` enables `nodejs_compat`. Moving DNS to Cloudflare means changing nameservers at Registro.br: first copy every existing record (WordPress/HostGator site, email MX).

## Local preview (no accounts)

```bash
npm install
npm run dev     # http://127.0.0.1:8765/pro/  and  /admin/  (login code is printed in the terminal)

```

## Rules enforced on the server
- Prices: cash < original; discount % equals the computed value (floor or round); installments × value ≥ cash; "menos de R$ X por mês" must be above the installment.
- Buy link: https on `kiwify.com.br` only. Social links: https on the matching site only. Videos: valid YouTube id or URL. Image: JPG/PNG/WebP (checked by file signature), ≤ 4 MB, stored in the Supabase bucket; only URLs of that bucket are accepted.
- Login: unknown emails get the same answer as allowed ones; max 3 codes per email per 15 min and 10 per IP per hour; a code lives 10 min, is single-use and locks after 5 wrong tries.

## Adding a page (`/black/`, home)
1. Add an entry to `PAGES` in `api/_lib/settings.js` with its defaults (identical to the HTML).
2. In the page: `data-page="<slug>"` on `<html>`, mark values like `/pro/index.html` does, load `/shared/site-settings.js`.
3. Add the slug to the admin tests. Prices on `/black/` are separate fields from `/pro/`.
